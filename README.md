# 澎湃小工具（pengpai-tool）

HyperOS 3 的 KernelSU 模块 + 配套管理 App。去广告、精简系统、屏蔽系统更新提示、全局高刷、充电温控与充电上限、CPU 限频、应用编译优化、机型修改、电池循环伪装……所有改动都有记录，都能一键恢复。

模块负责「开机保持」：每次开机按记录重新应用，系统更新或云控改回去的开关会被再次改回；App 负责「管理」：仿 HyperOS 设置的界面，所有操作最终都调用模块里的同一个脚本 `adclean.sh`，App 不运行时模块照样生效。

> 本项目的出发点是**只去广告和毒瘤，不伤系统功能**。小米服务框架、小米互联、投屏、小爱同学、定位、账号、查找手机等在脚本层面列入保护名单，任何情况下都会拒绝处理。

## 适用环境

| 项目 | 要求 |
| --- | --- |
| 系统 | HyperOS 3（Android 16）。主要在 REDMI K90（`songyuan`，OS3.0.306）上开发和实测 |
| Root | KernelSU（开发时为 ksud 3.3.1）。App 也能识别 KernelSU Next、SukiSU、APatch、Magisk 的管理器 |
| 可选 | LSPosed（新版 libxposed API 102），只有「我的设备美化」需要 |

部分功能和硬件相关，不支持的机型会在 App 里显示为不可用，而不是乱写节点：

- **充电控制**：支持小米 MCA 充电框架（REDMI K90 等）和高通 `qcom-battery`（小米 13 Ultra 等）两套驱动。
- **全局高刷**：可选档位按屏幕实际支持的显示模式列出（K90 为 60 / 90 / 120 / 144 / 165 / 185Hz）。
- **系统温度墙图表**：K90 自带一份预置温控表，其他机型需要在 App 里扫描一次。

## 安装

1. 在 [Releases](https://github.com/Android-Modules/pengpai-tool/releases) 下载 `HyperAdClean-vX.Y.Z.zip`，或按[从源码构建](#从源码构建)自己打包。
2. 在 KernelSU 管理器 →「模块」→「从本地安装」，选择 zip。安装过程会**自动装上管理 App「澎湃小工具」**。
3. 重启手机。
4. 在 KernelSU 管理器 →「超级用户」里给「澎湃小工具」授权 Root，然后从桌面打开它。

安装后模块**不会自动精简或修改任何东西**，所有功能默认关闭，需要你在 App 里逐项开启。

升级时直接安装新版 zip 覆盖即可：模块数据保存在 `/data/adb/hyperadclean`，不会因为升级丢失；新版 App 会在安装模块时自动覆盖旧版。

## 功能一览

App 首页分为五组，下面按首页顺序介绍。

### 系统精简

#### 系统精简（冻结 / 卸载）

- **推荐清单**：64 个已在 K90 上核对过包名和中文名的系统组件，按「推荐 / 可选 / 谨慎」分级，主要是广告、统计、推荐、云控类组件。
- **自定义**：从全部应用里自己挑选，分「用户应用 / 系统应用」两栏，显示图标、名称和包名，支持搜索；核心组件和保护名单里的应用会标出来，不能选。
- **已处理**：列出处理过的应用，可单个或全部恢复。
- 两种方式：**冻结**（`pm disable-user`，可随时解冻）或**卸载**（`pm uninstall -k --user 0`，只对当前用户卸载，系统分区里的 APK 不动）。
- 处理前自动把 APK 备份到 `/storage/emulated/0/HyperAdClean/apk/<包名>/`，即使系统里的副本丢失也能从备份重装。
- 开机时按记录检查一遍，被 OTA 或云控恢复的组件会重新冻结 / 卸载（可在设置里关闭）。

#### 去广告

- **hosts 拦截**：把模块生成的 hosts 绑定挂载到 `/system/etc/hosts`（在 init 的挂载命名空间里挂载，系统 DNS 解析立即生效，无需重启）。规则分组开关：
  - 小米系统广告与统计（19 个域名）
  - 第三方广告 SDK：穿山甲、优量汇、快手联盟、百度联盟等（16 个域名）
  - 反诈数据上传（6 个域名，在「反诈管理」里开关）
  - 自定义规则：每行一个域名，或标准 hosts 格式
- **系统推荐开关**：关闭调试日志自动上传、应用商店云端预下载、「打开方式」里的应用推荐。开启前记录原值，关闭时原样还原。

#### 广告设置

22 个直达入口，一键打开各系统应用里藏得很深的广告与个性化推荐开关：手机管家、应用商店、小米账号的系统广告、垃圾清理、下载管理、日历、天气、主题、钱包、小米社区、营业厅、负一屏、应用安装器、浏览器、小爱同学、搜狗输入法小米版、小米有品、澎湃 AI 引擎、全局搜索等，省去一层层找菜单。导出的页面不需要 Root 也能打开。

#### WLAN 日志清理

HyperOS 的 vendor 服务会在 `/data/vendor/wlan_logs` 写入 WLAN 调试日志和抓包文件，云控打开时单个抓包可达数百 MB。

- 按间隔（1 ~ 24 小时）定时清理，或超过阈值（50 ~ 500MB）立即清理。
- **拦截调试抓包**：检测到 `cnss_diag`、`tcpdump`、`sniffer` 等抓包服务或对应属性被打开时，停止服务并把属性改回 `false`。
- 正在被进程写入的文件只截断不删除（删除不会释放空间），驱动常驻的日志文件跳过。
- 保留每次清理、拦截的记录。

#### 反诈管理

- 禁用手机管家的支付页监控、欺诈态势采集、AI 反诈场景监控等后台组件，关闭短信风险提醒、验证码剪贴板提醒、屏幕共享防护、AI 通话预警、浏览器网页风险提醒等开关。
- 屏蔽反诈相关的数据上传域名（安装应用列表云扫描、反诈埋点等）。
- 单独开关「陌生号码智能识别」（来电号码发到黄页云端查询标记）。
- 第一次开启时备份全部原值，关闭时逐项还原。

#### 屏蔽系统更新

系统更新（`com.android.updater`）属于小米核心应用，系统不允许整包冻结，所以分四层处理：

1. 禁用它的 9 个检查组件（定时检查任务、开机 / 换卡 / 账号变化等广播接收器）。
2. 收回它的通知权限。
3. 用 iptables / ip6tables 按 uid 断网（自建 `hac_ota` 链，关闭时整链删除，不碰系统规则）。
4. 清掉「我的设备」里的新版本提示和桌面「设置」图标上的角标，并用 `inotifyd` 监听全局设置文件，更新程序从缓存里写回提示时 1 秒内再次清掉。

开机早期（系统服务还没起来时）就先用缓存的 uid 断网。关闭后全部恢复，系统更新会在下次检查时重新提示。

### 锁屏与显示

#### 全局高刷

三种方式：

| 方式 | 原理 | 特点 |
| --- | --- | --- |
| 智能 | 把 HyperOS 自己的刷新率设置改成目标值（设置界面只列出 120 / 90 / 60，但系统接受 144） | 滑动时到顶，静止 / 视频时照常降帧，最省电 |
| 强制（省电） | 在智能方式基础上，把 SurfaceFlinger 和 DisplayManager 的静止降帧等待从约 1.1 秒延长到 3 / 5 / 10 秒 | 操作时和停手后几秒内保持高刷，之后照常降帧；需要重启生效 |
| 强制 | 通过 SurfaceFlinger 强制显示模式，始终满帧 | 最流畅也最耗电，支持 165 / 185Hz |

强制方式下，系统在切换应用、打开相机、灭屏后会重新下发刷新率策略，所以模块带一个守护进程：亮屏时每秒读一次面板实际刷新率（sysfs 节点），不一致就立即锁回。守护循环里完全不启动外部进程，实测 CPU 占用约 0.09% 个核心。

另外提供开发者选项里的「显示刷新率」悬浮开关。

#### 字体大小

对系统字体做 0.80 ~ 1.60 的无极缩放（系统设置只有几个固定档位）。系统重启会还原这个值，模块开机后自动重新应用。

#### 状态栏图标

- 隐藏状态栏图标：网速、静音 / 振动、勿扰、闹钟、VPN、NFC、定位、蓝牙、耳机、热点、HD、飞行模式、投屏、各类互联等 30 种，立即生效。使用 HyperOS 自己的 `status_bar_hide_icon_slot_name`（AOSP 的 `icon_blacklist` 在 HyperOS 3 上隐藏不了静音 / 勿扰图标）。
- 状态栏通知图标的显示方式。

#### 色彩风格

部分机型的 `device_features` 里开启了 `support_simplified_colormode`，设置里的「色彩风格」只剩「专业原色 / 生动」两项。开启后模块在开机早期挂载一份把它改成 `false` 的副本，恢复「生动 / 鲜艳 / 高级模式」等完整选项。

副本的 SELinux 标签或内容校验不通过时宁可不挂载，避免整份设备配置失效。切换后重启生效。

#### 竖屏锁定

关闭自动旋转并锁定竖屏。控制中心或某些应用把它改回去时，守护按间隔（10 秒 ~ 5 分钟）检查并改回，记录每次被改的时间。

### 电池和性能

#### 电池健康度

实际满充容量与设计容量的比值，以及设计 / 实际容量、售后健康度（SOH）、循环次数（伪装时同时显示真实值）、温度、电池状态和充电状态。

#### 电池循环伪装

用 tmpfs（带正确的 SELinux 标签）生成伪装文件，再 bind-mount 覆盖系统读取的循环次数节点。**不写电量计芯片**，关闭或卸载模块即恢复真实值。

- 梯度映射：真实 < 500 次显示 20，≤ 600 显示 50，≤ 900 显示 80，更多显示 200。
- 固定值：始终显示指定次数。
- 真实循环次数始终显示在 App 里。转让或出售手机时请如实告知电池情况。

（由独立模块「电池循环次数伪装 Pro」集成而来。）

#### 充电控制

- **温控方式**：
  - 系统温控：不干预。
  - 自定义温控墙：电池温度低于设定值（30 ~ 48℃）时解除系统的充电温控限流，到达后交还系统，回落 2℃ 后再次解除。
  - 阶梯限流（米系亮屏快充的思路）：不解除温控，而是按电池温度分档自己写电流上限，例如低于 33℃ 10A、33 ~ 55℃ 6A……档位可自行编辑。
- **亮屏快充 / 息屏快充**分别开关。
- **快充电量区间**：电量达到设定值后交还系统温控。
- **充电上限**：充到指定电量（20 ~ 100%）停止充电，低于「上限 − 回充差值」再继续。停充方式可选「停止充电、继续供电」或「断开输入」。
- **过热停充**：电池温度达到设定值（38 ~ 50℃）暂停充电，回落 3℃ 后恢复。
- **充电曲线记录**：每 2 秒记录电量、电流、电压、电池 / 机身温度、系统温控上限等，按次保存最近 60 次，App 里可查看曲线、峰值 / 平均功率、充入容量。
- **系统温度墙**：解析 `mi_thermald` 当前温控场景的电流墙和限速等级，以及驱动里的 JEITA、快充阶梯表，用图表展示。

安全边界：本模块通过充电驱动的投票接口只投**自己的一票**，系统自身的高温停充、JEITA 等保护仍然有效；所有节点写入在重启后都会恢复默认。

#### 电池优化白名单

- 区分用户应用和系统应用，显示图标和数量。
- 加入白名单时，同时把应用在各个用户空间（含手机分身、工作资料）里的 PowerKeeper「省电策略」设为「无限制」并解除「受限」，避免退后台被冻结导致消息延迟。
- 开机自动重新加回，防止被系统清掉；在系统设置里改过的也会同步。

#### 处理器调整

按 CPU 簇（policy）限制最高频率。限频前记录原来的上限（可能本来就被系统或其他模块限制着），关闭总开关时精确恢复到原值，而不是硬件最大频率。开机自动重新应用。

#### 应用深度优化

- 选择应用（显示图标、名称、包名，支持搜索和全选），用 `cmd package compile` 以 `speed-profile` 或 `speed` 模式编译。
- 「后台优化」：立即执行系统的 `bg-dexopt-job`，相当于系统在充电空闲时做的优化。
- 圆环进度动画，中间显示当前正在编译的应用，下方列出最近完成的结果。编译在后台进行，离开页面也不会中断。

#### 远程进程守卫

`com.miui.securitycenter.remote` 偶尔会失控长时间满载。守卫按间隔（3 ~ 15 秒）采样它的 CPU 占用，超过阈值就结束它（系统会按需重新拉起）。采样只读 `/proc/<pid>/stat`，不启动外部进程。

（由独立模块 `baize_remote_cpu_guard` 集成而来。）

### 系统设置

#### 机型修改

- 381 款小米 / Redmi / POCO 预设机型，或自定义市场名称、认证型号、品牌、厂商、内部代号。
- 在 Zygote 启动前（post-fs-data）重放属性，新进程直接读到修改后的机型。
- 首次安装时记录固件原始机型作为基线；每次修改都有事务和回滚，失败自动恢复。
- 已打开的 App 读的是缓存，提供「重启框架」让所有 App 重新读取。

（由独立模块「动态机型修改」集成而来。）

#### 我的设备美化（需 LSPosed）

把「设置 → 关于手机」整页换成「雾蓝白」或「银灰香槟」主题。原有的 Logo、设备卡片、按钮只隐藏不删除，新页面的文字和点击都转给它们，改名、系统更新、存储等原功能不受影响。作用域只有「设置」。

#### 开发者选项

- 无需插卡即可打开开发者选项和 USB 调试，下拉通知栏也可以添加快捷开关。
- **无线调试配对码**：系统设置的配对码只发给设置自己，App 收不到，所以这里改用系统的二维码配对接口，由 App 生成配对码并显示端口，在电脑上执行 `adb pair IP:端口 配对码` 即可。
- **无线调试诊断**：每 30 秒记录一次无线调试的开关、端口、连接数等状态变化，用来排查「无线调试自己断开」的问题；只观察，不会保活或重新开启。不需要时可以关闭。
- 管理已配对的电脑，可单独取消配对。

#### 账号同步

一键关闭所有用户空间的「自动同步」（包括设置里看不到的手机分身空间）和「仅在 WLAN 下同步」，可选开机自动关闭。调用前先核对系统接口编号，不匹配就不动，避免误操作。

#### WIFI 密码 / 隐藏设置入口

- 查看已保存 WIFI 网络的密码。
- 打开系统里藏起来的原生设置页。

### 备份、日志与关于

- **备份目录**：默认 `/storage/emulated/0/HyperAdClean`，可修改。里面保存处理记录、开关原值、配置和 APK 备份；文件属主和 SELinux 标签与「下载」目录一致，文件管理器可以直接看到。重装模块或清除数据后可以从这里导入处理记录。
- **模块设置**：是否备份 APK、开机是否保持精简状态、卸载模块时是否自动恢复、默认处理方式（冻结 / 卸载）。
- **运行日志**：所有操作和开机检查的记录，可清空。

## 安全设计

- **保护名单**：系统核心（框架、系统界面、设置、电话、权限控制器、各 Provider 等）和常用功能（小米服务框架、推送、小米互联、投屏、小爱同学、定位、账号、查找手机、KernelSU 等）写在脚本里，App 和命令行都绕不过去。
- **全部可恢复**：每项改动前记录原状态，恢复时回到原状态，而不是统一改成「开启」。原本就冻结的应用恢复后仍是冻结。
- **不写持久分区**：hosts、色彩配置、循环次数都是挂载覆盖，刷机文件和系统分区不改动；充电和 CPU 节点重启即恢复默认。
- **不越过硬件保护**：充电控制只在驱动允许的范围内调整，内核的高温停充、JEITA 保护始终有效；不提供删除温控文件之类的操作。
- **与独立模块不冲突**：检测到「动态机型修改」「电池循环次数伪装」「远程进程守卫」的独立模块仍在启用时，对应功能自动让给旧模块，App 里可以一键停用旧模块。安装时还会迁移旧模块的配置和记录。

## 后台进程与耗电

只有开启对应功能才会启动后台进程。所有守护都用「读空管道超时」代替 `sleep`，循环里尽量只用 shell 内建命令读 sysfs / procfs，不额外启动进程。

| 进程 | 何时运行 | 检查频率 |
| --- | --- | --- |
| 刷新率守护 | 全局高刷选「强制」 | 亮屏每秒、灭屏每 2 秒 |
| 充电控制 | 开启充电控制或充电曲线记录 | 充电时每 1 ~ 2 秒，未充电每 10 秒 |
| 进程守卫 | 开启远程进程守卫 | 3 ~ 15 秒 |
| WLAN 日志 | 开启定时清理或拦截抓包 | 每分钟 |
| 竖屏锁定 | 开启竖屏锁定 | 10 秒 ~ 5 分钟 |
| 循环伪装 | 开启电池循环伪装 | 每 5 分钟 |

| 更新提示监听 | 开启屏蔽系统更新 | 只在设置文件被写入时触发 |

## 卸载

在 KernelSU 管理器里卸载模块并重启。开机完成后，模块会在后台：

- 卸载管理 App；
- 恢复全部冻结 / 卸载的应用和系统开关；
- 恢复系统更新、反诈组件、CPU 频率上限、刷新率设置；
- 删除 `/data/adb/hyperadclean`。

如果在「模块设置」里关闭了「卸载时自动恢复」，则只卸载 App，保留精简状态。备份目录里的文件不会被删除，需要的话可以手动删掉。

## 命令行用法

所有功能也可以在 root shell 里直接调用，每行输出一条记录，字段用 `|` 分隔：

```sh
S=/data/adb/modules/hyperadclean/adclean.sh

sh $S status                         # 推荐清单和已处理应用的状态
```

## 常见问题

**装完模块桌面没有「澎湃小工具」？**
安装时 App 装失败会在开机后自动重试；也可以解压 zip，手动安装里面的 `app/HyperAdClean.apk`。

**App 一直停在「正在检查 Root 权限」？**
KernelSU 不会弹授权框，需要在管理器的「超级用户」里手动给「澎湃小工具」授权。

**开了 hosts 拦截，某个应用的功能不正常？**
关闭对应的规则组即可立即恢复，无需重启。自定义规则里也可以只拦截你确认的域名。

**充电控制能不能把温控彻底关掉？**
不能，也不建议。高温下大电流充电会明显加速电池老化，甚至有安全风险。本模块只在电池温度允许的范围内放宽系统的限流，高温停充和硬件保护始终有效。

**系统更新后功能失效了？**
重启一次，开机检查会按记录重新应用。如果系统改了内部接口（例如无线调试、账号同步用到的调用编号），对应功能会检测到不匹配并拒绝执行，等待适配。
